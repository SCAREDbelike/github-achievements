# Workflow Notes

Las mejoras se desarrollan en ramas y se integran mediante pull requests.

## Convenciones usadas

- `feature/` para funciones nuevas.
- `fix/` para correcciones.
- `docs/` para documentación.
- `achievement/` para prácticas directamente relacionadas con achievements.

## Validación

Cuando un repositorio contiene código ejecutable, se recomienda añadir GitHub Actions y verificar que el CI esté verde antes de mergear.

## Filosofía del laboratorio

Los achievements son una consecuencia de utilizar correctamente GitHub, no un sustituto de proyectos reales. Las prácticas de este repositorio quedan documentadas para que la actividad tenga valor como aprendizaje.
