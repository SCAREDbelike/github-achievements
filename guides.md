# GitHub Workflow Guide

## Flujo recomendado

1. Crear una rama desde `main`.
2. Hacer un cambio pequeño y útil.
3. Crear un commit con mensaje claro.
4. Subir la rama.
5. Abrir un pull request.
6. Verificar CI y cambios.
7. Mergear cuando esté listo.
8. Mantener `main` estable.

## Buenas prácticas

- No trabajar directamente sobre `main` para cambios grandes.
- Evitar commits gigantes.
- Usar PRs con un objetivo claro.
- No crear actividad vacía solamente por aumentar números.
- Usar los logros como incentivo para aprender funciones reales de GitHub.

## Logros y aprendizaje

Este repositorio utiliza issues, pull requests, reacciones y documentación para practicar funciones reales de GitHub mientras se registran posibles achievements.
